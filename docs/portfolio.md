# Campus RAG：简历与面试项目概述

## 一句话介绍

我独立构建了一个面向中文数据结构课程资料的可评测 RAG 问答系统：它通过混合检索从本地 Markdown 中获取证据，再由 DeepSeek 生成带来源标注的回答，并对拒答、引用、索引版本、延迟和用户反馈进行追踪。

## 我解决的问题

- 课程笔记很长、术语多：采用 BGE 向量检索 + TF-IDF 精确检索 + RRF 融合。
- 短片段容易丢失上下文：实现父子分块，检索子块、向模型提供相邻章节上下文。
- 模型可能在资料不足时编造：增加证据充分性门槛，低置信时不调用模型而直接拒答。
- “回答看起来不错”不可量化：建立困难检索集、拒答集、LLM Judge、分类指标和回归测试。
- 文档更新会导致旧索引悄悄失效：用语料指纹检测索引是否 fresh，并通过发布质量门禁阻止带着旧索引上线。

## 技术栈

Python、FastAPI、Sentence Transformers、BAAI/bge-small-zh-v1.5、TF-IDF、RRF、DeepSeek API、GitHub Actions、unittest。

## 可量化结果（当前小规模课程语料）

- 困难检索集：`recall@1 = 100% (16/16)`。
- 资料内/资料外拒答集：`accuracy = 100% (7/7)`，拒答 precision/recall 均为 100%。
- 本地混合检索稳态延迟：median `148.135 ms`，P95 `161.930 ms`，不含 DeepSeek。
- 自动化回归测试：60 项通过。

这些数据只代表当前 6 份课程笔记和人工标注集，不能外推为通用 RAG 指标；项目保留了复现命令与评测集，后续可以随着真实失败样本持续扩大。

## 面试时可展开讲的工程取舍

1. 为什么先做 Hybrid RAG，而不是直接上 GraphRAG：小语料下召回、延迟和成本更可控。
2. 为什么 Reranker 尚未默认上线：本机缺少约 1.1 GB 权重，且现有困难集已满分；应先收集真正能区分算法的失败样本。
3. 证据门槛的风险：阈值需要随领域和语料重新校准，因此实现了独立的拒答评测和显式质量门禁。
4. 如何处理用户点踩：通过本地 Trace、反馈报告和检索诊断，先判断是资料、召回、融合排序、生成还是引用问题，再把修复案例加入回归集。
